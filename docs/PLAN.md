# 三人游戏俱乐部（TRIO GAME CLUB）— 架构与实施计划（第一阶段）

## 一、整体架构

```
trio-game-club/
├─ package.json            # npm workspaces：根目录统一管理
├─ shared/                 # 前后端共用的 TypeScript 类型（事件名、状态结构）
├─ server/                 # Node.js + Express + Socket.IO
│  └─ src/
│     ├─ index.ts          # 启动 HTTP + Socket.IO；生产环境同时托管前端静态文件
│     ├─ rooms/            # RoomManager：房间创建/加入/离开/断线重连/准备/投票选游戏/积分
│     ├─ games/            # 每个游戏一个模块，实现统一接口 GameEngine
│     │   ├─ undercover/ draw/ quiz/ werewolf/ monopoly/ cards/ turtlesoup/ detective/
│     └─ data/             # 题库、词库、卡片、案件（JSON，可扩充）
├─ client/                 # React + TypeScript + Vite + CSS
│  └─ src/
│     ├─ pages/            # 首页、房间大厅
│     ├─ games/            # 每个游戏一个界面组件
│     ├─ components/       # 复古风 UI：纸张卡片、骰子、棋子、扑克牌、木质棋盘
│     └─ styles/           # 主题变量（米白/酒红/墨绿/金/深棕）
└─ docs/                   # 规划与规则文档
```

### 核心设计原则

1. **服务器权威**：所有游戏状态只存在服务器内存里，客户端只发送"意图"（如"我投票给 B"），服务器验证后才改变状态。
2. **按玩家过滤视图（防泄密）**：服务器不广播完整状态，而是为每位玩家单独生成 `getViewFor(playerId)`。卧底词、狼人身份、私人卡、标准答案等只出现在有权查看的玩家的视图里。
3. **统一游戏接口**：

```ts
interface GameEngine {
  id: string;
  start(players: Player[]): void;
  handleAction(playerId: string, action: Action): Result; // 验证 + 修改状态
  getViewFor(playerId: string): GameView;                 // 个人视图
  onTick?(): void;                                        // 倒计时
  isOver(): boolean;
  getScores(): Record<string, number>;                    // 本局积分
}
```
   新增游戏只需实现这个接口并注册，大厅无需改动。
4. **防重复提交**：每个动作携带 `actionId`（客户端生成），服务器记录已处理的 id 并检查"该阶段该玩家是否已操作"。
5. **断线重连**：玩家首次进入时服务器发一个 `playerToken`，存在浏览器 localStorage。断线后座位保留 120 秒，刷新或重连时凭 token 恢复身份与个人视图；超时则离座，房主断线则自动转移房主。
6. **房间**：4 位数字房间号，每个房间独立的状态对象；最多 3 人，满 3 人且全部准备后房主才能开始。
7. **积分**：每局结束后按名次加分，累计到房间排行榜；游戏记录（谁玩了什么、谁赢了）保存在房间内，并写入 `server/data/records.json`（无需数据库，初学者友好）。
8. **实时通信**：Socket.IO 事件分两类：`room:*`（大厅）和 `game:action` / `game:view`（游戏内）。
9. **响应式**：CSS 以手机竖屏为基准设计，再用媒体查询扩展到平板/电脑；画板使用 Pointer Events 同时支持触摸与鼠标。
10. **部署（第八阶段）**：免费方案——Render / Railway / Fly.io 免费额度之一，一个服务同时托管前后端。会在该阶段再与你确认选择，不会擅自付费。

## 四、八款游戏规则设计

### 1. 谁是卧底（3人）
- 1 卧底 + 2 平民。平民得到词 A，卧底得到相近词 B（如"牛奶/豆浆"），谁都不知道自己是不是卧底。
- 流程：发词 → 每人依次用一句话描述（不能含原词）→ 自由讨论（聊天框，90 秒）→ 同时投票 → 得票最多者出局。
- 3 人局特别规则：**只有一轮投票决胜**——投中卧底，平民胜；投错（或平票），卧底胜。为增加悬念，若第一轮平票则进行第二轮描述 + 投票，仍平票则卧底胜。
- 积分：平民胜各 +2，卧底胜卧底 +4。每局换卧底（轮换）。词库 ≥ 60 组。

### 2. 你画我猜
- 3 回合，每人当一次画家。画家看到词语，在画板上作画（画笔、粗细、颜色、橡皮、清空、撤销）；笔画以点序列通过 Socket 实时广播。
- 猜词者在聊天框输入答案，服务器判断；60 秒倒计时，答对越早得分越高（猜对者 3~1 分，画家每有人猜对 +1）。
- 画家的词只发给画家；猜词输入只有正确与否的反馈，避免他人抄答案。词库分难度，≥ 100 词。

### 3. 答题竞赛
- 10 题（单选 / 判断），类别：文学、历史、地理、文化、常识。每题 15 秒，三人同时作答。
- 得分：答对 10 分 + 速度加成（最多 5 分）；答错 0 分。所有人答完或超时后揭晓答案并显示三人选择。
- 答案在揭晓前不会发给客户端。题库 ≥ 80 题（JSON，可扩充）。最终显示排名并计入积分榜（第一 +3、第二 +2、第三 +1）。

### 4. 三人狼人杀 ★ 请重点确认
传统狼人杀要 6 人以上，直接缩小会失衡，所以专门设计了一个"1 狼 + 1 预言家 + 1 守卫"的三人版本：

**身份组合（每局随机分配，每人只知道自己的身份）**
| 身份 | 阵营 | 技能 |
|---|---|---|
| 狼人 ×1 | 狼 | 每晚可咬一人；白天可以假装其他身份 |
| 预言家 ×1 | 好人 | 每晚查验一人，得知"是否为狼人" |
| 守卫 ×1 | 好人 | 每晚守护一人（可守自己，不能连续两晚守同一人），被守者当晚免死 |

三人局只有一狼，所以**好人阵营 2 人、狼人 1 人**，信息不对称由"各自只知道自己的身份"制造。

**夜晚（所有人同时行动，服务器收齐后结算）**
1. 狼人选择咬杀目标；预言家选择验人（得到私密结果）；守卫选择守护目标。
2. 结算：被咬且未被守护者死亡；若守护成功则平安夜。

**白天**
1. 公布死亡情况（平安夜或某人死亡）。
2. 存活者依次发言（每人 45 秒文字发言，可声明身份或撒谎）。
3. 投票放逐：存活玩家投票，得票最多者出局；平票则无人出局。

**胜负条件（保证每局必有结果）**
- 狼人被放逐 → 好人胜。
- 好人阵营在任意时刻仅剩 1 人且狼人存活 → 狼人胜（即 2 人对 1 狼时狼只需再杀一人或骗过票）。
- 最多 3 个昼夜，若仍无结果 → 狼人胜（防止拖延）。

**平衡说明**：2 好人 vs 1 狼，且好人有预言家验人，若首夜预言家查到狼则次日几乎必胜；但预言家若被咬死，剩下守卫 + 狼，白天投票 50% 概率，所以狼有真实机会。守卫的存在让"首夜狼咬预言家"可能被挡下，增加推理。为避免第一夜预言家被秒杀过强，**首夜狼人不能咬人（首夜平安夜）**，仅预言家验人与守卫守护。

> 若你想要不同的身份（如换成"女巫""猎人"）、或改变首夜规则，请告诉我，实现前可以改。

### 5. 大富翁
- 28 格环形棋盘：起点、土地 16 块（4 个色组）、2 机会、2 命运、监狱、免费停车、入狱格、税务等。
- 初始资金 15000；经过起点 +2000。掷双骰（服务器掷，防作弊）→ 棋子沿路移动。
- 空地可购买；他人地产自动收租；同色组集齐后可升级建筑（空地 → 1~3 级房屋 → 酒店），租金递增。
- 机会/命运卡：随机事件（得钱、罚款、前进、入狱等）。
- 破产：现金不足时先自动变卖建筑，仍不足则破产出局，其地产回收。
- 结束：只剩一名玩家，或达到 30 回合上限——按"现金 + 地产价值"排名。

### 6. 抽卡游戏
- 四类卡：命运卡（影响积分）、任务卡（要求现实互动，如"用方言说一句话"，由其他两人投票是否完成）、惩罚卡、特殊事件卡（如交换分数）。
- 轮流抽卡，共 3 轮。卡片有"公开 / 私人"属性：公开卡全员可见；私人卡只发给抽到的人（如"秘密任务"，期满结算）。
- 卡库放在 JSON 中，后期可直接添加卡片。

### 7. 海龟汤
- 一人当主持人，另两人推理；每局轮换。
- 主持人可从内置题库（≥ 40 题）选题，或手动输入"汤面"和"汤底"。**汤底仅主持人可见。**
- 推理者轮流提问（是非题），主持人点击"是 / 不是 / 无关 / 是也不是"。
- 推理者可随时"提交答案"，主持人判定；猜中者 +3，主持人在题目被解出时 +1；也可由主持人"公布汤底"结束。

### 8. 谁是侦探
- 内置 ≥ 5 个案件，每案含：背景、3~5 位嫌疑人及关系、8~12 条线索（分散在若干"地点"中）。
- 搜证：每人每轮有 2 次行动点，可前往地点获得线索；线索可选择"公开给全队"或"私藏"。
- **合作模式**：线索默认共享，三人一起讨论，最终提交一个答案，对则全队 +4。
- **竞争模式**：线索各自私有，可选择是否共享；各自提交"凶手 + 动机"，凶手对 +4，动机选项对再 +2，先交且对额外 +1。
- 凶手与动机的标准答案在提交前不发给任何客户端。

| 风险 | 处理办法 |
