# 第七阶段：全面测试报告

## 怎么重新跑一遍

在项目根目录运行：

```
npm test
```

它会自动启动一个全新的临时服务器（加速的计时器、空的数据目录），依次运行所有测试，最后打印汇总表，约 5 分钟。测试结束后会自动清理。

## 测试中发现并已修复的问题

1. **游戏名称不一致**：大厅里叫“侦探推理”，房间里叫“谁是侦探”；抽卡、大富翁、猜数字的图标也不一致。已改成名称和图标只有一个来源（`catalog.ts`），并加进矩阵测试，以后不一致会直接报错。
2. 第六阶段的旧测试里有几处写得太脆弱（依赖随机抽到的题型、遇到“接完无路可走”的成语会误报），已改成稳定的写法。

其余 113 个组合第一次就通过，没有发现游戏逻辑错误。

## 还存在的问题和限制（如实列出）

### 未完成的功能
- **双人本地轮流游戏（同一台设备两人轮流玩）没有做**。现在的双人模式都是两台设备联网。
- 计划书里的“游戏开始倒计时”“房间关闭”还没做（目前是房主点开始即开始，房间在最后一个人离开后自动消失）。
- 声音与音效、复古像素艺术风格改造、设置页面都没有做。
- 单人模式只有剪刀石头布有电脑对手；没有五子棋、井字棋、国际象棋这类棋类游戏。
- 计划里的 66 款游戏已完成 29 款（另有 5 款计划外的：答题竞赛、脑筋急转弯、三人狼人杀、大富翁、抽卡），剩下的 37 款标记为“开发中”，没有伪装成已完成。

### 质量和内容
- 题库 503 题全部由我手写，**没有人工审核**；马华文学只有 22 题，成语接龙词库只有约 390 个成语。
- 没有用多台真实设备、真实网络做过测试：所有联机测试都是脚本和浏览器模拟。反应速度挑战的成绩包含网络延迟。

### 运行方面
- **没有“超时自动行动”**：吹牛骰子、猜数字、记忆翻牌等需要轮流的游戏，如果有人一直不操作，游戏会停在那里，只能由房主中止。（成语接龙、答题等有计时的游戏不受影响。）
- 房间和进行中的游戏只存在服务器内存里，服务器重启后会消失。
- 数据保存有约 0.4 秒延迟；服务器被强制杀掉时，最后 0.4 秒的数据可能丢失。
- 玩家身份靠浏览器里保存的编号，不是账号：换浏览器或清除数据就是新玩家。
- 部署到 Render 免费版后，休眠或重启会清空全部数据（战绩、好友、自定义题库）。想长期保存需要付费磁盘或外部数据库。
- 房间号只有 4 位数字，没满的房间知道号码就能加入。
- 数据存成一个 JSON 文件并全部放在内存里，适合朋友之间使用，不适合成千上万人。

## 数据备份与恢复

数据文件是服务器 `storage/store.json`（或环境变量 `DATA_DIR` 指定的目录）。
- **备份**：服务器停止时（或任何时候）复制这个文件即可。
- **恢复**：停止服务器，把备份文件放回原位置，再启动。
- 写入时先写临时文件再改名，所以写到一半断电不会损坏原文件。
